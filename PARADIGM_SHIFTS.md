# From Data Engineer to AI Engineer

Five real moments from this project where the Data Engineer instinct and the reality of building an AI agent reached different answers. In chronological order.

| Problem | DE Thinking | AI Paradigm |
|---|---|---|
| The agent explored on its own (it queried six dates without being asked) and, when a call failed, invented an infrastructure cause with no evidence. | A missing parameter either gets rejected or falls back to one fixed default. A failure cause is never improvised. | The model improvises by default. The fix combined two layers: the prompt now requires it to ask before acting, and the code enforces a hard cap of fourteen days that no instruction can override. |
| The original cost estimate came out ten times lower than the real cost measured in CloudWatch. | A pipeline's cost is calculated once and stays stable as long as the code does not change. | Every turn resends the full prompt and every tool schema. Cost grows with each reasoning step, not with added functionality. Only a real measurement revealed this. |
| Did the agent correctly compute the standings (wins and losses) from the real game data? | Write the calculation, run a test once, and if it passes, trust it will always pass. | One run proves nothing. The same real data, run through three different models, produced three different answers, all wrong. A bigger model was not more reliable. The real fix was moving the arithmetic out of the model and into deterministic code. |
| The agent contradicted the user's explicit premise about the current roster, asserting a fact from its own training instead. | The source of truth always wins over any prior assumption. There is no room for ambiguity. | The model treats its training knowledge as just another fact, even against the user and the real date. A prompt fix raised accuracy from zero to seventy five percent, but it remains probabilistic, not a guarantee. |
| The Lambda stopped returning real data right after confirming the timeout fixes worked, as if the external API were simply down. | If the failure looks the same everywhere, the source is down. Retry later and move on. | Not necessarily. The actual origin of the request (a cloud IP versus a residential one) can be silently blocked, with no explicit error code at all. The real clue was comparing the exact failure type across two environments, not assuming a general outage. **To be continued in the next article.** |
